# Personal OS｜人生元系统

> 不是寻找一套永远正确的人生答案，而是建立一套可以不断发现错误、修正判断、改善行动的系统。

**版本：V0.1（公开草案）**　｜　**定位：个人认知系统 + 决策工具 + 行为实践 + 复盘机制**

## 一、为什么建立 Personal OS？

现实生活的问题看似分散：职业怎么选、时间怎么分配、遇到喜欢的人如何相处、是否值得消费、要不要继续一个项目。它们往往共享底层结构，例如资源配置、不确定性、风险、边界、机会成本、继续与退出。

因此，Personal OS 不只是收集知识，而是将信息转化为**可检验的判断和可执行的行动**；同时留下来源、条件、反例和复盘，使它可以随经验持续更新。

### 系统要优化的四种能力

1. **解释能力**：分清事实、推断、价值判断，识别事情背后的机制。
2. **决策能力**：在信息不完美的情况下作出有成本意识的选择。
3. **行动能力**：把原则转化为行为，能试验、执行，也能适时停止。
4. **修正能力**：让结果反过来改变认知，而不是为原来的判断找借口。

**不追求**：永不犯错、无条件套用名人观点、把所有领域简化为一个公式、用复杂笔记替代现实行动。

## 二、总体架构：领域是入口，母题是连接器

```text
现实输入：文章 / 书籍 / 经历 / 对话 / 观察
                      ↓
             素材收集（Inbox）
                      ↓
        事实、解释、价值判断分别记录
                      ↓
              归属领域 Domain
                      ↓
           提取底层母题 Question
                      ↓
         连接已有原则 / 模型 / 案例
                      ↓
           形成假设、问题或决策
                      ↓
            行动 / 低成本试验
                      ↓
           检查：继续 / 调整 / 退出
                      ↓
           复盘与证据、版本更新
                      ↺
```

### 系统中的七类知识对象

| 对象 | 负责回答 | 示例 |
|---|---|---|
| 领域 Domain | 这件事发生在人生哪个方面？ | 爱情、职业、健康 |
| 母题 Mother Question | 这属于哪一类反复出现的根本问题？ | 何时坚持、何时退出？ |
| 原则 Principle | 我暂时认可的判断规则是什么？ | 保持现状也应进入选项集合 |
| 模型 Model | 我用什么方法分析？ | 机会成本、预期价值、退出合约 |
| 来源 Source | 观点从哪里来、原文说了什么？ | 书籍、文章、自己的观察 |
| 案例 Case | 规则在现实中表现怎样？ | 健身房选择、项目推进 |
| 复盘 Review | 应保留、修改还是废弃什么？ | 预期与结果的差异 |

**关系规则**：一篇来源可关联多个母题；同一母题可跨多个领域；原则和模型可以应用于多个案例。不要机械地把所有知识锁进唯一文件夹。

## 三、八个人生领域

| 编号 | 领域 | 主要探索方向 |
|---|---|---|
| D01 | 社会 Society | 社会规则、组织、合作、竞争、权力与责任 |
| D02 | 友情 Friendship | 信任、互惠、边界、投入与关系维护 |
| D03 | 爱情 Romance | 自我认识、吸引、表达、互相尊重、适配、冲突、退出 |
| D04 | 金钱 Money | 消费、储蓄、投资、风险、财务选择权 |
| D05 | 健康 Health | 运动、恢复、睡眠、饮食、身心健康 |
| D06 | 时间 Time | 优先级、注意力、精力、机会成本 |
| D07 | 职业 Career | 能力积累、职业选择、环境、发展路径 |
| D08 | 学习 Learning | 学习策略、知识组织、迁移、反馈 |

**元认知 Meta-Cognition** 不作为第九个人生领域，而作为横跨全部领域的基础工具层：未知信息处理、事实与推断、概率、认知偏差、实验、决策和退出。

## 四、首批跨领域母题

母题是可持续追问的问题，不是看起来很深刻的口号。

| ID | 母题 | 常见关联领域 |
|---|---|---|
| MQ-001 | 什么值得投入我的时间、金钱和注意力？ | 时间、金钱、职业、爱情 |
| MQ-002 | 信息不完整时，何时分析、何时行动？ | 学习、职业、社会 |
| MQ-003 | 失败损失多大？决定是否可逆？ | 金钱、职业、健康 |
| MQ-004 | 何时坚持、调整或退出？ | 全领域 |
| MQ-005 | 哪些是事实，哪些只是我的解释？ | 社会、友情、爱情 |
| MQ-006 | 短期舒服与长期利益是否冲突？ | 时间、健康、学习 |
| MQ-007 | 是真正成长，还是只有成长的感觉？ | 学习、职业、健康 |
| MQ-008 | 保持现状的隐性机会成本是什么？ | 全领域 |
| MQ-009 | 哪些约束是不能用其他优点抵消的？ | 健康、职业、关系 |
| MQ-010 | 能否用一个小实验获得关键新信息？ | 全领域 |
| MQ-011 | 我的期待和他人的实际行为是否一致？ | 友情、爱情、合作 |
| MQ-012 | 这个结论在什么条件下会失效？ | 全领域 |

初始母题不追求完整。只有当新问题长期无法合理归类时才新增；重复问题优先建立交叉链接。

## 五、知识如何进入系统？

### 1. 先拆解，不直接吸收

新内容进入 Inbox 后，提取：**核心命题、作者证据、推理机制、适用条件、可能反例、来源链接、对我行为的影响**。明确区分：

- **事实**：可核对的观察或数据。
- **解释**：对事实的因果推断或理论。
- **价值观**：我认为什么重要；它不必伪装成客观定律。
- **行为建议**：基于事实、解释和价值观，下一步怎么做。

### 2. 每条观点都有状态

```text
素材 Material
    ↓ 有清楚命题与来源
候选假设 Hypothesis
    ↓ 经验证或与较强证据相符
实用规则 Tested Rule
    ↓ 多情境适用、边界清楚、经反例检验
核心原则 Core Principle
```

这是管理状态，不是自动按使用次数升级的科学证明。遇到反例可**降级、修改、拆分或归档**；不得因为某观点是自己喜欢的，就跳过验证。

### 3. 每次新增，都要检查四种关系

- **支持**：给已有观点增加独立证据。
- **补充**：带来新边界、新机制或新场景。
- **冲突**：结论不同，先核对定义、证据质量与适用条件。
- **重复**：没有新增信息时只补来源，不重复造原则。

### 4. 发布前做一道隔离

个人原始经历、聊天记录、他人身份、健康和财务细节**默认私有**。公开文章是经过本人审核、去标识化并保留必要来源的衍生内容，不是将私人案例目录整体发布。

## 六、行动引擎：把认知变成可检验的决策

遇到具体问题，调用独立模块 **《个人快速判断与退出模型》**，而不是在知识库里无限延伸讨论。

```text
目标与现状 → 硬约束 → 选项与代价 → 可逆性
              ↓
      信息价值 / 低成本试验
              ↓
          决策与行动
              ↓
          退出合约
              ↓
    检查：继续 / 调整 / 退出
              ↓
     案例复盘 → 认知更新
```

**成果不只是“想通了”**：更好的成果是形成一个可执行决定，并记录什么证据会改变它。

## 七、从爱情领域开始做第一个样板

爱情模块作为一次完整的系统验证：

1. 自我认识：欣赏、孤独、投射、依恋与真正的需求。
2. 认识与吸引：呈现真实自我，保持尊重，不追求操纵。
3. 沟通：提问、倾听、表达兴趣、清晰传递意图。
4. 兴趣识别：理解信号具有不确定性，不能把猜测当事实。
5. 边界与同意：双方有拒绝、改变主意和退出的权利。
6. 长期适配：价值观、生活方式、冲突解决、互惠程度。
7. 关系调整与退出：不因投入时间长就否认不适配。
8. 复盘：我观察到了什么、我臆测了什么、下次如何改善？

历史文章中的观点可以提炼、验证、批判，不应把将他人当作目标或操纵对象的技巧升级为核心原则。

## 八、一个跨领域例子

选择健身场所，表面归属 **健康**，实际还关联 **金钱、时间**。它调用的母题可能是 MQ-001（资源投入）、MQ-003（可逆性）、MQ-008（现状成本）、MQ-010（小实验）。

这类问题不一定要单独创造“健身房理论”。更好的方式是：保存案例，链接到共同母题，让同一个模型在未来职业选择或项目投入中复用。

## 九、公开网站如何呈现？

网站可以分为四层访问体验：

1. **领域地图**：从社会、友情、爱情等领域进入。
2. **母题页面**：集中展示一个根本问题、相关模型和跨领域案例。
3. **文章与认知卡**：论点、来源、条件、反例、版本记录。
4. **决策工具**：可填写的四宫格、退出合约和复盘模板（未来版本）。

推荐优先做可阅读、可检索、可交叉链接的静态页面；交互和 AI 自动提取放到后续。**内容为主，网页只是呈现层**。

## 十、系统迭代与成功标准

| 阶段 | 要实现什么 | 完成标志 |
|---|---|---|
| V0.1 | 架构、母题、两篇核心说明、模板 | 能新增一条观点且有来源与状态 |
| V0.2 | 爱情模块试点 | 至少一个主题形成“来源→假设→案例→复盘”闭环 |
| V0.3 | 真实案例试运行 | 决策记录能在检查点回看并修正 |
| V0.4 | 网站化 | 两篇核心文档与分类入口可公开访问 |
| V1.0 | 跨领域知识网络 | 同一母题能连接不同领域的真实案例 |

**评价方式**：不是知识条数，而是能否更清楚地区分事实与解释、减少重复犯错、明确下一步行动、发现旧模型的失效边界。

---

**系统原则**：允许修订，保留版本；尊重证据，承认未知；记录失败，而不是抹掉失败。Personal OS 是一个长期开放的工作草案。
